# Gumbo 1.0 — native Mac, Settings and library reliability

> Historical record: names and source paths use current Gumbo spelling for navigation. Results predate the new app identity; see [identity and distribution](GUMBO-IDENTITY.md).

This batch addresses [#37](https://github.com/svoltolini/gumbo/issues/37), [#38](https://github.com/svoltolini/gumbo/issues/38), [#20](https://github.com/svoltolini/gumbo/issues/20), [#23](https://github.com/svoltolini/gumbo/issues/23) and [#30](https://github.com/svoltolini/gumbo/issues/30), with further work on navigation, performance, accessibility and remote-access guidance. Marketing version remains **1.0**, and the source build remains **202609142150**. At the owner's request, intermediate batches are merged without TestFlight uploads; the final consolidated candidate will receive a new build number.

## Native desktop behavior

The Mac app now has its own library browser, compact collection headers, selectable and sortable song tables, native toolbar/search, and a Now Playing inspector with a usable queue. Window resizing keeps the sidebar, content and player usable; a smaller window puts volume in a popover. The main window is singular, can be reopened after closing, and closing it leaves playback running. Settings uses the standard menu command and its own adaptable category window.

Song-table selection, Return, double-click and Space provide keyboard playback. Sorting runs in a cancellable background worker and preserves selection when the collection is unchanged. Playlist entries have occurrence identities, so selecting or removing one repeated song preserves the other occurrence. Queue selection jumps to the exact occurrence without reconstructing the queue. A queue menu captures the displayed entries and command revision, rejecting a stale action after playback changes. App-wide Space interception was removed because it also intercepted typing and controls in Settings.

Album, artist, playlist, Downloads and search screens use native desktop layouts. Search can switch to the first matching result category, shows loading/empty states, and returns from an opened result when the query changes or Find is invoked. Catalogue-only revisions retain the search path. Go to Album is routed through the Mac navigation owner, and profile/source/session changes clear old navigation and pending actions. Context menus and sheets recheck the captured source, session and collection before playing or editing. Genre rename/merge and decade browsing remain available.

Runtime checks found and corrected a missing environment dependency in AppKit-hosted table cells that crashed Songs, and separate selection/sheet state that opened Add to Playlist with zero songs. The final sheets carry one identifiable payload. Native Mac playlist rows have full-row click targets, and genre editing uses a focused, bordered text field.

## Settings and accurate controls

iPhone and iPad Settings now use grouped system forms with native toggles, pickers and disclosure navigation. Mac uses category navigation and grouped form panes. Family, profile management/editor, invite/join sheets, Privacy Details, Diagnostics, Genre Names and Release Notes follow the same platform conventions. The Mac PIN editor uses native secure fields with four ASCII digits and matching confirmation; existing unlock policy and mobile/TV entry remain intact. Permission checks, draft/session validation, failure handling, and destructive-action confirmations are preserved.

The unimplemented Gapless control and product claims were removed, using the removal option in #20. Compatibility fields remain readable in saved profile data. Playback completion, repeat/shuffle, failure and interruption behavior continue to be tested; this release does not claim gapless playback. Unranked “Top songs” is now “Songs”, instructions and release notes are platform-specific, and sample screens report their actual catalogue/playlist counts and duration.

## Metadata and download responsiveness

Refresh reuses song tags only when the source, path, size and available modification timestamp match. Fractional timestamps survive catalogue persistence. Legacy catalogues migrate on refresh; a server without timestamps keeps its size/path fallback, with a confirmed **Read Song Tags Again** action for an explicit reread.

A changed revision or explicit reread clears retry backoff while retaining the last good tags until the read succeeds. Failed listing/reads preserve the old metadata. A successful read with removed tags restores filename/folder/default values, including track/disc numbers and album-level fallbacks. Tests cover actual synthetic MP4 tag changes at unchanged file size, failures, removed tags, migration and 5,000/15,000 unchanged songs requiring zero media reads.

Download-status aggregation and filesystem checks now run outside the main actor. Results are scoped to source/profile/generation; cancellation or a changed source rejects stale completion. Visible controls refresh after structural changes, on return to the foreground and periodically while visible, so missing files do not stay marked downloaded. Playback still authoritatively checks the actual file before using it. Progress polling does not continuously cancel a large in-flight status scan.

## Remote access

Onboarding and Server Settings include a native, optional Remote Access Help page. It explains installation on the NAS and each connecting device, the full MagicDNS hostname, HTTPS certificate requirements, DSM credentials, family network access separate from iCloud invitations, and the unverified independent Watch route. Direct HTTPS remains an alternative. Explicit HTTP does not imply that Gumbo has detected or verified a VPN. The wording was checked against the official [Synology](https://tailscale.com/docs/integrations/synology), [sharing](https://tailscale.com/docs/features/sharing) and [MagicDNS](https://tailscale.com/docs/features/magicdns) documentation. Real home/away, VPN-off and certificate-error journeys remain in #29/#12.

## Validation and limits

The complete Release package suite passed **219 tests in 11 suites** with normal parallelism, including GumboCore and GumboShared/widget authorization. The focused metadata/playback suite also passed **44 tests in three suites**. Production Mac, iOS (including Watch/widgets) and TV Release builds passed; the final queue-menu guard passed an additional Mac Release compilation. TV reports only the routine skipped AppIntents extraction notice. Results and the native fixture checklist are recorded in [native UI evidence](evidence/native-ui-checks.json). All fixtures use synthetic data, dedicated temporary storage, ordinary local WAV playback and mock CloudKit. No real NAS, family account or personal music files were modified.

The actual Mac interface was exercised at wide and approximately 900-point minimum window widths, in light/dark appearance, with six long-name profiles. Checks include keyboard/sorted playback, queue navigation, repeated playlist entries, native creation and rename actions, search, profile isolation, window reopening, Settings and player accessibility values. The iPhone 17 Pro/iOS 26.5 simulator was checked at standard and Accessibility Extra Large text sizes; nested server labels and decorative icon overflow were corrected. Mac Settings category, nested navigation, appearance and resizing were checked separately. These are visual/accessibility-tree checks, not a claim of complete spoken VoiceOver or physical-device acceptance.

The performance investigation and source hashes are in [navigation evidence](evidence/navigation-performance.json). Controlled earlier traces isolate the core changes while retaining the preceding UI; they must not be presented as measurements of the redesigned Mac interface. The 15,000-saved-song filesystem probe reduced measured main-thread heartbeat delay from roughly 100 ms to roughly 1 ms. This is a focused probe, not an end-to-end frame-time result.

Separate final native-interface recordings still failed #35's smoothness criterion: the 5,000-song loop contained **33 hitches of at least 100 ms, maximum 266.67 ms**; the 15,000-song loop contained **39, maximum 716.67 ms**. Repeated-route visits alone contained 30 and 36 respectively. Full-library playlists were the largest repeated stalls, and Artists also exceeded 100 ms on most visits. Startup is reported separately. These results justify continued optimization; this batch does not establish global smoothness. #35 stays open for that work, cold profile activation and incoming remote merges.

Axiom HIG and SwiftUI guidance informed the work, using reference revision `71d342b65068d45787f5b6f45ce9deaf58f9629d`. Real NAS/2FA, two-device CloudKit, Watch, CarPlay, background transfers, accessibility and motion acceptance remain separately tracked in #12 and their originating issues. Public policy/support URLs, store metadata and App Review access remain in #13/#14. No distribution artifact or TestFlight availability is claimed for this batch.
